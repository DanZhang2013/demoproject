# Demo Project

## 项目简介

这是一个演示项目，用于展示标准的项目结构和开发规范。

## 代码编写规范

### 通用规范

1. **代码风格**
   - 保持代码简洁、清晰、易读
   - 使用有意义的变量名和函数名
   - 避免过长的函数，建议单个函数不超过50行
   - 适当添加注释，说明复杂逻辑的实现思路

2. **命名规范**
   - 变量名和函数名使用驼峰命名法（camelCase）
   - 类名使用帕斯卡命名法（PascalCase）
   - 常量使用全大写字母和下划线（UPPER_SNAKE_CASE）
   - 文件名使用小写字母和连字符（kebab-case）

3. **代码组织**
   - 相关功能的代码应该放在一起
   - 合理使用模块化，提高代码复用性
   - 遵循单一职责原则，每个函数/类只做一件事

4. **错误处理**
   - 必须处理可能出现的异常情况
   - 提供有意义的错误信息
   - 避免空的catch块

5. **性能优化**
   - 避免不必要的循环嵌套
   - 合理使用缓存
   - 注意内存管理，避免内存泄漏

### 版本控制规范

1. **提交信息**
   - 使用清晰、描述性的提交信息
   - 提交信息应简要说明本次修改的内容和目的
   - 建议使用中文或英文，保持一致性

2. **分支管理**
   - `main/master` - 主分支，保持稳定
   - `develop` - 开发分支
   - `feature/*` - 功能分支
   - `bugfix/*` - bug修复分支

3. **代码审查**
   - 提交代码前进行自我审查
   - 重要功能需要团队成员进行代码审查
   - 及时响应审查意见
